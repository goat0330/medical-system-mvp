# 中国住院全流程 Golden Patient v1

## 这是什么
一套**完全虚构、可重复、可断言**的中国住院测试 Episode，用来验证 `medical-system-mvp` 的整条链路，而不是只演示页面。

患者：**虚构患者甲，男，43岁**<br>
住院：2026-09-18 → 2026-09-23<br>
主要诊断：**胆囊结石伴急性胆囊炎（K80.000x002）**<br>
主要手术：**腹腔镜下胆囊切除术（51.2300）**

## Golden 正确结果
- EMR、手术记录、出院记录、病案首页、医保结算清单：诊断/操作一致。
- HIS费用合计：**13,400.00**；基金支付 + 个人负担：**13,400.00**，用于勾稽测试。
- DRG 3.0 规则预期：`MDCH → HC4 → HC45`。
- DIP 3.0 实际结果：主要诊断 `K80.000x002` 命中官方工作簿“不纳入分组的主要诊断”前缀 `K80.000`（来源行 1180），返回 `EXCLUDED_PRINCIPAL_DIAGNOSIS`，不产生 DIP 病种组。
- 原包中的 DIP 预期只匹配了并项规则、没有执行排除规则；集成版现以完整规则执行器结果为准。

## 包内内容
- `data/`：Episode 与文书索引。
- `documents/`：住院病案首页、入院记录、首次病程、日常病程、两类查房、术前小结、手术记录、术后首次病程、出院记录。
- `clinical/`：生命体征、检验、影像、医嘱、病理。
- `billing/`：HIS费用与医保结算清单数据。
- `grouping/`：DRG/DIP 3.0 确定性期望。
- `qc-variants/`：3个故障注入样本。
- `sql/`：PostgreSQL 测试库表结构与种子数据。
- `tests/validate-golden.mjs`：无依赖自校验脚本。
- `integration/`：面向 `goat0330/medical-system-mvp` 的接入说明和可替换 fixture。

## 三个故障样本
1. **病案首页漏手术**：应被跨文书/首页完整性质控阻断。
2. **结算清单凭空多出 ENBD 操作**：应命中 EMR↔清单不一致；本病例的主要诊断已被 DIP 排除，因此此变体不能再声称会改变 DIP 分组结果。
3. **费用明细被改 1 元**：应命中金额勾稽失败并阻断申报。

## 自校验
在本目录运行：

```bash
node tests/validate-golden.mjs
```

预期输出以 `PASS Golden patient base dataset` 开头。

## 标准与政策依据
- 国家卫生健康委：WS/T 500 系列《电子病历共享文档规范》，覆盖住院病案首页、入院记录、首次/日常病程、上级医师查房、术前、术后、出院记录、住院医嘱等。
- 国家卫生健康委：《住院病案首页数据填写质量规范（暂行）》。
- 国家医保局：医保办发〔2021〕34号《医疗保障基金结算清单》《医疗保障基金结算清单填写规范》。
- 国家医保局：2026-09-02 正式发布按病种付费 3.0 版分组方案。
- DRG/DIP Golden 预期值来自用户提供的两份 3.0 XLSX 规则快照，SHA-256 见 `grouping/SOURCE_NOTES.md`。

## 边界
本包不是医疗建议，也不是生产医保结算结果。患者、医生、机构、费用与支付金额全部为测试数据；医保待遇金额仅用于软件金额勾稽。
