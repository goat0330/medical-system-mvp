# 全流程六域质控与分组输入完整性

## 目标

统一链路：

```text
Evidence Store
→ Patient Fact Store
→ Conflict / FactDecision
→ Projection
→ 六域 QC
→ QualityIssue
→ 人工处理
→ 下游重算
```

六域分别是：单文书、跨文书/跨源、病案首页、医保结算清单、DRG/DIP、医保审核。

## 分组输入必须先质控

DRG/DIP Grouper 不负责替用户判断输入是否可信。进入正式规则执行前增加 `INPUT_INTEGRITY_VALIDATION`：

- 主要诊断不能为空；
- 主要诊断不能重复出现在其他诊断；
- 其他诊断不能重复；
- 主要操作不能重复出现在其他操作；
- DRG 路径主要诊断必须被当前官方 DRG 3.0 `DI_*` 规则集合精确支持，或属于明确的待人工确认本地映射候选。

校验失败返回 `INVALID_INPUT`，支付测算 `NOT_CALCULATED`，正式分组状态 `BLOCKED_BY_INPUT_INTEGRITY`。

## 工作台来源版本

每个 Episode 的工作台输入与患者/文书源数据建立 fingerprint。源数据变化时：

1. 当前工作台归档；
2. 不删除归档；
3. 从最新患者事实重新映射；
4. 后续正式分组必须重新锁定。

避免“患者顶部是 K80.3，工作台却恢复很久以前的 A15.400”这类不可追溯状态。

## 六域不是六套数据底座

六域全部复用：

- `ClinicalFact`
- `EvidenceItem`
- `FactConflict`
- `FactDecision`
- `QualityIssue`

因此同一个年龄冲突可以同时影响病案首页、结算、分组和医保审核，但来源只保存一次，人工裁定也只做一次。

## 本轮远端规则核验

针对截图中的 `A15.400`：

- 当前 DIP 3.0 编译规则中存在该编码；
- 当前 DRG 3.0 编译规则的 `DI_*` 精确集合中不存在 `A15.400`；
- `K80.302`、`K80.101` 在 DRG 3.0 `DI_*` 精确集合中存在。

因此原工作台“统一使用 DIP 诊断搜索结果，再直接送给 DRG”是不安全的。本轮将目录展示与分组前输入校验拆开：选择器只负责候选，`INPUT_INTEGRITY_VALIDATION` 是进入 Grouper 前的最终确定性闸门。
