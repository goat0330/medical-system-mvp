# MVP 业务闭环

## 1. 页面主线

    Episode 总览
      → 惠每模板病历书写
      → 惠每住院病案首页
      → 193 项语义映射的医保结算清单
      → 国家 DRG/DIP 3.0 输入检查
      → 智能审核
      → 模拟提交、医保反馈、对账

## 2. 当前文书范围

保留：

- 住院病案首页
- 入院记录
- 首次病程记录
- 日常病程记录
- 主治医生首次查房记录、主治医生查房记录
- 手术记录
- 术前小结
- 出院记录

明确不做：

- 会诊
- 接班
- 阶段小结
- 一般护理记录单
- 死亡记录
- 死亡病例讨论记录

如果结算清单需要护理、死亡或其他专项字段，系统应显示“未采集/不适用”，不得由 AI 推断成已发生事实。

## 4. 可验收演示用例

使用完全虚构的外科住院病例：

1. 生成入院、首次病程、日常病程、查房、术前、手术、出院草稿。
2. 在惠每病案首页模板适配层查看结构化字段。
3. 把诊断、手术、出院和费用事实映射到结算清单分组。
4. 运行清单质控，检查必填、时间顺序、诊断/手术一致性和金额勾稽。
5. 创建快照并执行本地 mock 提交，得到反馈和对账差异。
6. 查看国家 DRG/DIP 3.0 输入是否完整；正式规则包未接入时明确阻断，不显示伪造组别。
7. 智能审核展示风险线索、证据引用和人工确认入口。

## 5. 验收标准

- 同一 Episode 贯穿病历、首页、结算清单和审核，不复制粘贴另造病例。
- 病案首页来源标识为 HmEditor，文书草稿有证据引用和医生确认状态。
- 六个排除模板不出现在启用模板列表。
- 结算清单能从病例事实确定性生成，并能指出缺失字段。
- 快照、幂等键、反馈和对账结果可重复回放。
- 国家 DRG/DIP 3.0 未有可执行规则包时显示真实状态，不把旧版规则结果冒充 3.0。
- 智能审核输出“风险线索 + 证据 + 人工处置”，不直接输出“骗保”定论。
