# 规则版本与地方化边界

更新时间：2026-09-22

## 本轮决定

本轮 MVP 只使用国家版本 DRG 3.0 / DIP 3.0 的版本元数据与输入契约，暂不启用武汉本地 3.0。这样可以先把病历、编码、结算清单和审核闭环跑通，不把尚未核验的地方权重、费率、细分组或接口伪装成正式结果。

国家医保局于 2026-09-02 发布按病组和病种分值付费 3.0 版分组方案通知，附件包含国家 DRG 3.0 与 DIP 3.0 方案：

- https://www.nhsa.gov.cn/art/2026/9/2/art_104_21975.html
- https://www.nhsa.gov.cn/art/2026/9/2/art_14_21978.html

## 运行状态

| 层级 | MVP 状态 | 说明 |
|---|---|---|
| 国家 DRG 3.0 | 已绑定版本元数据 | 正式附件已发布；可执行规则包待放入 rules/vendor/ |
| 国家 DIP 3.0 | 已绑定版本元数据 | 正式附件已发布；DIP 病种/分值计算待导入 |
| 武汉地方配置 | 暂不启用 | 不使用地方权重、费率、系数或清算接口 |
| 结算清单 | 已实现本地生成与质控 | 真实提交先用 mock，可回放 |
| 智能审核 | 已实现线索与证据展示 | 不输出“骗保”定论 |

## 分组输入契约

    patient_attributes
    principal_diagnosis
    secondary_diagnoses
    procedures
    discharge_status
    settlement_list
    clinical_evidence

每次正式分组还必须记录：

    national_rule_version
    payment_mode
    effective_date
    input_snapshot_id
    grouping_path
    execution_status

execution_status 在规则包未接入时只能是 not_ready 或 demo，不能写成正式分组结果。

## 后续接入顺序

1. 固定国家 DRG/DIP 3.0 官方附件的版本和来源。
2. 把可执行规则包放到独立 vendor 目录，先跑单病例输入/输出 smoke。
3. 把分组路径和每条规则命中原因接到当前审核证据链。
4. 取得统筹区真实支付参数后，再增加模拟支付金额。
5. 最后再新增武汉 profile，不修改国家 3.0 核心输入输出。
