# P1 Operational Workbench 覆盖包

这一版修复上一版“规则是真的，但页面只是演示卡片”的问题。覆盖后，`DRG / DIP 3.0` 和 `智能医保审核` 会变成可操作工作台。

## 真实数据链

当前患者选择 → Episode → 已保存病历/病案首页快照 → 结构化字段映射 → 医保结算清单 → Policy Profile → DRG/DIP 3.0 → 正式分组快照 → ClaimDetail → 审核 → EvidenceBundle → 人工复核 → 修改 → 重跑。

### 当前患者直接映射

工作台会读取主系统当前选中的患者，并读取本地保存的病历快照：

`medical-system:document:<episodeId>:<templateId>`

优先从已保存病案首页/病历数据元提取：主要诊断、主要诊断编码、主要手术/操作、性别、年龄、入出院时间；未保存字段才回退到 Episode。

## DRG / DIP 工作台

可以直接修改：

- 支付政策配置（支付方式由 Policy Profile 决定）
- 性别、年龄、新生儿日龄/体重
- 主要诊断
- 其他诊断增删
- 主要手术/操作
- 其他手术/操作增删

按钮：

- `从当前患者重新映射`
- `保存当前输入`
- `执行院内预分组`
- `锁定结算快照并执行正式分组`

结果来自用户提供的官方 DRG/DIP 3.0 Excel Rule Pack，并展示逐步 trace 与 Excel 来源。

## 医保审核工作台

ClaimDetail 支持新增、删除、编辑：项目编码、名称、计费时间、数量、单价、金额。

当前确定性审核已执行：

- 结算清单数据质量
- 编码标准化
- 数量 × 单价 = 金额
- 费用时间是否在住院期间
- 同日同项目完全重复记录
- DRG/DIP 反事实重新分组
- 风险对应 EMR/HIS/病案事实 EvidenceBundle

人工复核支持：审核通过、退回医院、规则不适用、转稽核；操作按患者保存。修改病例或费用后，旧正式分组自动视为过期，需要重新锁定、重新分组和重新审核。

## 真实性边界

- 国家 DRG/DIP 3.0：使用包内两份官方 Excel 编译规则。
- 武汉权重/费率、DIP点值：没有核验的生产参数不会伪造；工作台不提供地方测试支付参数输入，未核验时返回 `PENDING_LOCAL_PARAMETERS` 且不生成支付金额。
- 国家/地方医保智能监管“两库”完整知识点包尚未包含；当前 L2 只运行数据本身可以确定的规则，并预留正式 Rule Pack 接口。
- “医保侧正式分组”在本地复刻执行国家规则，不能等同于真实医保生产平台远程返回。
